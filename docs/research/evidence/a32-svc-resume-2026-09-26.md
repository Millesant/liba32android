# A32 SVC resume evidence — 2026-09-26

## Current CPU seam

The Dynarmic adapter already receives `CallSVC(uint32_t)`, but currently
discards the immediate and reports only the generic exception boolean. The
execution result already returns general registers and CPSR, while requests
currently rebuild CPSR solely from the selected Arm/Thumb mode.

## Compatibility motivation

Fresh static inspection of the supplied ARMv7 inputs found these external
platform-library names across VLC/FMOD:

- `libc.so`
- `libdl.so`
- `libm.so`
- `liblog.so`
- `libandroid.so`
- `libEGL.so`
- `libGLESv2.so`
- `libstdc++.so`

Representative undefined imports include pthread/libc/libdl routines,
`__android_log_*`, EGL/GLES functions, and C++ ABI/runtime symbols.

Features 020-022 now provide requester-aware provider composition and exact-name
catalog images. A distinguishable resumable guest trap is the next prerequisite
for implementing those platform compatibility images as thin ARM32 stubs.

The third-party binaries remain external evidence and are not committed.
