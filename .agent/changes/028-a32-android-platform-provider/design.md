# Design — explicit Android platform provider policy

## API

Add:

- `A32AndroidPlatformAccessDecision { Allow, NotFound, Failed }`;
- caller-owned `A32AndroidPlatformAccessPolicy::decide(requester,name)`;
- `A32AndroidPlatformProvider`.

The provider owns one `Elf32DependencyCatalogEntry` generated by the
feature-027 helper and one catalog-provider object whose span points at that
entry. It borrows the shim bytes and policy object.

Copy and move are deleted because copying the internal catalog would preserve a
span into the old object's entry storage.

## Resolution

`resolve_for(requester,name,max)`:

1. if `name != "liblog.so"`, return NotFound and do not call policy;
2. call policy with the exact borrowed requester/name views;
3. Allow -> delegate to `Elf32DependencyCatalogProvider::resolve`;
4. NotFound -> NotFound;
5. Failed/unknown decision value -> Failed.

`resolve(name,max)` delegates with an empty requester.

Delegating on Allow reuses existing validation for empty image, maximum image
bytes, canonical identity, and owned result copying.

## Provider-chain use

An application-local catalog remains first in
`Elf32DependencyProviderChain`. A platform provider follows it. Generic chain
logic already forwards the exact requester to each attempted child; feature 028
does not modify ELF provider APIs.

## Real integration

The feature-027 consumer/shim integration is changed from a direct catalog
provider to:

`empty application catalog -> platform provider -> liblog shim`.

It requires one policy call carrying requester `android-log-consumer` and
requested name `liblog.so`, then retains all prior graph/relocation/execution
assertions.

## Non-goals

No interpretation of requester identities as namespace names or paths; no
namespace links; no permitted/search paths; no automatic process/platform
catalog construction.
